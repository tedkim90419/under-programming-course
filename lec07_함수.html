01

함수 (Function)의 필요성

💡함수란?

특정한 기능을 수행하는 독립된 프로그램 블록으로, 전체 프로그램을 기능 단위 모듈로 나누는 데 사용합니다.

  • C 언어로 작성된 프로그램은 하나 이상의 함수를 가짐 — 함수는 프로그램의 기본 building block
  • 함수는 이름(식별자)을 가지며, 이름으로 호출함
  • 입력 데이터(인자)를 받아 처리 후 결과를 반환할 수 있음

😓함수 없이 — 코드 중복

// 같은 연산을 여러 번 반복 작성
result1 = a * a + 2*a + 1;
// ...
result2 = b * b + 2*b + 1;
// ...
result3 = c * c + 2*c + 1;
// 수정 시 모든 곳을 바꿔야 함 😱

✅함수 사용 — 모듈화

int calc(int x) {
  return x*x + 2*x + 1;
}
result1 = calc(a);
result2 = calc(b);
result3 = calc(c);
// 수정은 함수 한 곳만! 🎉

함수 단위 모듈화의 장점

📖가독성 향상

중복 코드를 함수로 모듈화 → 간결한 코드

♻️코드 재사용

다른 프로젝트에도 함수 단위로 재사용 가능

🔧유지보수 용이

기능 개선 시 해당 함수만 수정하면 됨

📦
함수의 종류 표준 라이브러리 함수: C 언어가 기본 제공 — printf(), scanf(), sqrt(), strlen() 등
사용자 정의 함수: 프로그래머가 직접 작성 — 본 강의의 핵심!

03

return 문

↩️return 문의 역할

return 문을 만나면 함수의 실행은 즉시 종료되고, 제어는 호출한 곳으로 돌아갑니다.

📝return 문 형식

return;            // void 함수
return expression; // 값 반환

// 다양한 표현식 예시
return 1;
return ++a;
return (a * b);
return x + y;

⚡핵심 특성

  • 괄호 있어도 되고 없어도 됨
  • 수식의 계산값이 반환됨
  • return 문 개수 제한 없음 (0개도 가능)
  • 반환형이 다르면 자동 형변환
  • 몸체 끝 }를 만나도 함수 종료
절대값 — 복수 return 문C
// 실수 x의 절대값을 반환하는 함수
double absolute_value(double x)
{
  if (x >= 0.0)
    return x;      // ← 여기서 종료
  else
    return -x;     // ← 또는 여기서 종료
}
자동 타입 변환 — int → floatC
float f(char a, char b, char c)
{
  int i;
  // ...
  return i; /* int → float 자동 변환 */
}
// 컴파일러가 반환형(float)에 맞게 변환
⚠️
반환 타입과 실제 반환값의 타입이 다르면 자동 변환이 일어납니다. 의도치 않은 데이터 손실이 발생할 수 있으므로 주의하세요!
void 함수 — return 없음C
// 화면에 별(*)을 출력하는 함수
void print_stars(void)
{
  for (int i = 0; i < 30; i++)
    printf("*");
  // return 문이 없음
  // ← "}" 를 만나면 자동 종료
}
💡
return 문이 없으면 함수 몸체의 끝인 }를 만날 때 자동 종료됩니다. void 함수에서 중간에 빠져나오고 싶다면 return;을 사용하세요.

함수 호출 (Function Call)

📞함수 호출 흐름

  • C 프로그램의 실행은 항상 main() 함수로부터 시작
  • 함수 이름을 만나면 해당 함수가 호출(call)됨
  • 호출자(caller)는 피호출자(callee)가 종료될 때까지 대기
  • 피호출자 실행 완료 → 제어가 호출자로 복귀

📋 Call-by-Value (값에 의한 호출)

📦인자는 복사되어 전달된다!

함수가 호출되면 인자 값들은 메모리에 복사되어 매개변수에 전달됩니다.

  • 전달된 인자 값의 개수와 타입이 매개변수와 일치해야 함
  • 함수 내에서 매개변수 값을 변경해도 원본에 영향 없음
  • 인자: 호출 시 전달하는 값 / 매개변수: 함수 헤더의 변수
call_by_value.c — 인자 복사 전달
C 
int get_max(int x, int y)  // x ← 10, y ← 20 (복사!)
{
  if (x > y) return x;
  else       return y;
}

int main(void) {
  int value;
  value = get_max(10, 20);  // 인자: 10, 20
  printf("max = %d\n", value);  // 20
  return 0;
}
📌
Parameters vs Arguments 매개변수(Parameters): 함수 헤더에 정의된 변수 — int x, int y
인자(Arguments): 호출 시 전달하는 실제 값 — 10, 20
호출 시 순서대로 복사해서 전달: x ← 10, y ← 20
05

배열과 함수 (Call-by-Reference)

⚡배열 전달은 다르다!

배열을 함수에 전달할 때는 배열 원소 전체가 복사되는 것이 아니라, 배열의 시작 주소(포인터)가 전달됩니다. 이를 Call-by-Reference라 합니다.

  • 함수 내에서 배열 원소를 수정하면 원본 배열이 변경됨
  • 함수 내에서 인자로 전달된 배열의 크기를 알 수 없음 → 별도 파라미터로 전달
arraySum.c — 1차원 배열 전달
C 
#include <stdio.h>

// arr[]: 1차원 배열임을 알려줌 (크기 생략 가능)
// n   : 배열 원소 개수를 별도 파라미터로 받음
int arraySum(int arr[], int n)
{
  int i, sum = 0;
  for (i = 0; i < n; ++i)
    sum += arr[i];
  return sum;
}

int main(void) {
  int arr1[3] = { 1, 2, 3 };
  printf("sum = %d\n", arraySum(arr1, 3));
  return 0;
}
sum = 6

2차원 배열 전달

📏
다차원 배열 매개변수 규칙 매개변수 정의 시 각 차원의 크기를 지정해야 합니다. 단, 최상위 차원(첫 번째 차원)의 크기만 생략 가능합니다.
sum2dArray.c — 2차원 배열 전달
C 
#define ROWS 2
#define COLS 3

// arr[][COLS]: 열 크기 COLS는 반드시 명시!
// 첫 번째 차원(행)은 생략 가능
int sum2dArray(int arr[][COLS], int rows)
{
  int sum = 0, i, j;
  for (i = 0; i < rows; i++)
    for (j = 0; j < COLS; j++)
      sum += arr[i][j];
  return sum;
}

int main(void) {
  int arr2d[ROWS][COLS] = {{1,2,3},{4,5,6}};
  printf("sum = %d\n", sum2dArray(arr2d, ROWS));
  return 0;
}
sum = 21

함수 원형 선언 (Function Prototype)

📣왜 필요한가?

컴파일러는 함수를 사용하기 전에 그 함수의 정보를 알아야 합니다. 함수 정의보다 함수 호출이 먼저 나오는 경우, 미리 원형(prototype)을 선언해서 컴파일러에게 함수 존재를 알려줍니다.

✂️원형 선언 방법

함수 정의의 헤더 부분만 추출한 후 끝에 세미콜론(;)을 붙임

// 함수 정의 (전체)
int compute_sum(int n) { ... }

// 함수 원형 선언 (헤더 + 세미콜론)
int compute_sum(int n);   // ✅
int compute_sum(int);      // ✅ 이름 생략 가능
int compute_sum(n);        // ❌ 타입 필수!

📐소스 코드 구조 가이드라인

  • 사용자 정의 함수의 원형을 소스 최상단에 모두 선언
  • 또는 함수 정의를 main() 앞에 배치
  • 라이브러리 함수는 헤더 파일(#include)이 원형 역할
prototype_example.c — 권장 구조
C 
#include <stdio.h>

/* ① 함수 원형 선언 — 소스 최상단에 모두 선언 */
int compute_sum(int n);
void print_result(int result);

/* ② main 함수 */
int main(void) {
  int s = compute_sum(100); // 원형 선언 덕분에 OK
  print_result(s);
  return 0;
}

/* ③ 함수 정의 — main 뒤에 위치해도 OK */
int compute_sum(int n) {
  int i, result = 0;
  for (i = 1; i <= n; i++) result += i;
  return result;
}
void print_result(int result) {
  printf("결과 = %d\n", result);
}
🔍
컴파일러가 함수를 인식하는 3가지 방법 ① 함수 호출 부분이 나오기 전에 함수 정의가 있는 경우
② 명시적 함수 원형 선언이 있는 경우
③ 표준 헤더 파일 포함(#include)으로 라이브러리 함수 원형 사용

🔒블록 단위 참조 범위

변수는 그 변수가 선언된 블록 내에서만 사용(참조)이 가능합니다. 블록이 중첩된 경우, 내부 블록에서 같은 이름의 변수를 재정의하면 외부 블록 변수는 가려(shadow)집니다.

전역 영역 (Global scope)
전역 변수
global_var
main() 블록 (outer block)
a = 2
printf(a) → 2 출력
내부 블록 (inner block) — a가 재정의됨
a = 5 (outer a를 가림)
printf(a) → 5 출력
printf(++a) → 3 출력 (outer a = 2+1)
LAB: scope1.c — 블록 중첩 Scope
C 
#include <stdio.h>
int main(void)
{
  int a = 2; /* outer block a */
  printf("%d\n", a);    // 2 출력
  {
    int a = 5; /* inner block a — outer a를 가림 */
    printf("%d\n", a);  // 5 출력
  } /* inner a 소멸 → outer a 복귀 */
  printf("%d\n", ++a); // 3 출력 (outer a)
}

지역 변수 vs 전역 변수

지역 변수 (Local) 전역 변수 (Global)
선언 위치 함수(블록) 내부 함수 외부
참조 범위 해당 함수(블록) 내부만 소스 파일 전체 (extern: 다른 파일까지)
수명 함수 호출 시 생성, 종료 시 소멸 프로그램 전체 실행 기간
초기값 쓰레기 값 (명시적 초기화 필요) 자동으로 0으로 초기화
저장 위치 Stack 메모리 Data 세그먼트

📦지역 변수 예시

int compute_sum(int n) {
  int i, result = 0; // 지역변수
  for (i=1; i<=n; i++)
    result += i;
  return result;
}
int main(void) {
  int sum; // main의 지역변수
  sum = compute_sum(100);
  // i, result는 여기서 접근 불가!
}

sum ↔ i, result 서로 독립. 이름 중복 허용!

🌐전역 변수 예시

int global = 123; // 전역변수

void sub1() {
  printf("%d\n", ++global); // 124
}
void sub2() {
  printf("%d\n", ++global); // 125
}
int main(void) {
  sub1(); sub2();
  return 0;
}

모든 함수에서 공유 → 값이 누적됨

⚠️
전역 변수 남용 주의! 전역 변수는 프로그램 전체에서 공유되므로 어디서든 수정될 수 있어 버그 추적이 어렵고 유지보수가 힘들어집니다. 함수 매개변수로 주고받는 방식을 우선하고, 전역 변수는 꼭 필요한 경우에만 사용하세요.

⚖️같은 이름의 전역 + 지역 변수

LAB: shadow.c — 지역 변수가 전역을 가림C
int a = 33;  /* 전역 a */
int main(void) {
  int b = 77;
  printf("a = %d\n", a);  // 33 (전역 a)
  printf("b = %d\n", b);  // 77
  return 0;
}
void some_func(void) {
  int a = 11;  /* 지역 a — 전역 a를 가림! */
  // 이런 패턴은 혼선을 일으키므로 피할 것
}

같은 이름의 전역/지역 변수가 공존하면 지역 변수가 우선됩니다. 혼선 방지를 위해 이런 패턴은 피하세요!

저장 유형 (Storage Classes)

🗄️Storage Class란?

변수 선언 앞에 붙는 키워드로 실제 저장 영역과 수명(lifetime)을 결정합니다.

Keyword Storage Class 사용 위치 Scope Lifetime 초기값
auto automatic 함수/블록 내부 local 블록 진입 시 생성, 종료 시 소멸 쓰레기
register register 함수/블록 내부 local 블록 진입 시 생성, 종료 시 소멸 쓰레기
static (지역) static (local) 함수/블록 내부 local 프로그램 전체 (permanent) 0

⚡auto class

지역 변수의 기본(default) 저장 유형. auto 키워드는 보통 생략합니다.

이름의 유래: 선언된 블록 시작 시 메모리 자동(automatic) 할당, 블록 종료 시 자동 회수

int x;         // 같은 표현
auto int x;  // 보통 auto는 생략

⚡register class

컴파일러에게 해당 변수를 CPU 레지스터에 저장하도록 요청합니다. 자주 사용하는 루프 카운터 변수에 효과적.

레지스터 할당이 어려우면 자동으로 auto처럼 메모리에 저장됨. 최근 컴파일러는 자동 최적화를 잘 하므로 사용 빈도 낮음.

register int i;
for (i = 0; i < 100; i++)
  sum += i;
// i가 CPU 레지스터에 저장 → 빠른 접근

🔋static 지역 변수

지역 변수처럼 해당 블록 내에서만 접근 가능하지만, 값과 저장 공간이 프로그램 종료까지 유지됩니다.

LAB: staticVar.cC
void sub(void) {
  int           auto_count   = 0; // 매번 0으로 초기화
  static int   static_count = 0; // 최초 한 번만 초기화
  auto_count++;
  static_count++;
  printf("auto=%d, static=%d\n",
         auto_count, static_count);
}
int main(void) {
  sub(); sub(); sub(); return 0;
}
auto=1, static=1
auto=1, static=2
auto=1, static=3

🔒static 전역 변수

전역 변수 앞에 static을 붙이면 참조 범위가 해당 소스 파일로 제한됩니다. 다른 파일에서는 접근 불가.

/* file1.c */
static int file_private = 0;
// 이 파일 내 함수들만 접근 가능
// 다른 소스 파일에서는 extern으로도 접근 불가

파일 단위 캡슐화(encapsulation)에 유용합니다.

🔗extern class

다른 소스 파일에 정의된 전역 변수를 현재 파일에서 사용할 때 선언합니다.

file1.c + file2.c — extern 사용C
/* file1.c — 변수 정의 */
int a = 1;
int b = 2, c = 3;

/* file2.c — 외부 변수 참조 선언 */
extern int a;  // file1.c의 a를 사용함을 선언
int f(void) {
  int b, c;  // 지역변수 b, c (file1의 b,c와 별개)
  a = b = c = 4;
  return (a + b + c);  // 12
}

재귀 함수 (Recursion)

🔄재귀 함수란?

자기 자신을 호출하는 함수입니다. 복잡한 알고리즘을 간결하게 표현할 수 있습니다.

  • Fibonacci 수열, Factorial(계승), GCD (최대공약수)
  • 정렬/탐색 알고리즘, Tower of Hanoi 문제

🛑Base Case (종료 조건)

더 이상 재귀 호출을 하지 않고 직접 값을 반환하는 조건. 반드시 있어야 무한 재귀를 방지!

🔁General Recursive Case

자기 자신을 호출하되, 반드시 base case에 가까워지도록 인자를 변경해서 호출.

factorial.c — 재귀로 구현한 n!
C 
/*
 * n! = 1           (n == 1)  ← base case
 * n! = n × (n-1)! (n  > 1)  ← general case
 */
int factorial(int n)
{
  if (n == 1)              /* base case */
    return 1;
  else                       /* general recursive case */
    return (n * factorial(n - 1));
}
▶ 인터랙티브 재귀 호출 스택 시뮬레이터 — factorial(n)
(max 8)
🟢 호출(PUSH) → 🔵 base case → 🟠 반환(POP)

재귀 vs 반복(Iterative) 비교

🔄재귀 (Recursive)

  • 코드가 더 짧고 직관적
  • 개념 이해 후 구현 쉬움
  • 호출마다 스택 메모리 사용
  • 처리 시간이 더 길 수 있음
  • 스택 오버플로우 위험

🔁반복 (Iterative)

  • 메모리 효율적
  • 일반적으로 더 빠름
  • 스택 오버플로우 위험 없음
  • 코드가 길어질 수 있음
  • 복잡한 알고리즘은 이해하기 어려울 수 있음
💡
언제 재귀를 쓸까? 응용의 특성에 맞게 재귀와 반복 중 신중하게 선택하세요. Fibonacci, Factorial처럼 수학적 정의가 재귀적인 문제에 재귀가 자연스럽습니다. 단, 성능이 중요한 응용에서는 반복 방식을 고려하세요.
