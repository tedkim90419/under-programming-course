전처리기 (Preprocessor) 개요

⚙️전처리기란?

컴파일 직전 단계에서 소스 파일을 변환하는 도구입니다. # 기호로 시작하는 줄이 전처리 지시어(preprocessing directive)입니다.

  • 전처리 지시어의 효력 범위: 지시어 위치부터 파일 끝까지 (또는 다른 지시어로 무효화될 때까지)
  • 실제 C 코드가 아닌 텍스트 치환 작업

02

#include 지시어

📂#include — 파일 삽입

다른 파일의 내용을 읽어와 소스 코드를 확장합니다. 주로 헤더 파일을 포함할 때 사용합니다.

🔵#include <filename>

시스템 헤더 파일 — 시스템이 제공하는 라이브러리 함수와 매크로 상수를 위해 사용합니다.

  • 시스템 지정 위치에서 검색 (Linux: /usr/include)
  • 예: <stdio.h>, <math.h>

🟢#include "filename"

사용자 정의 헤더 파일 — 프로그래머가 만든 함수 프로토타입, 전역 매크로 등을 포함할 때 사용합니다.

  • 현재 소스 코드 위치 또는 지정 폴더에서 탐색
  • 예: "class_info.h", "mylib.h"
💡
헤더 파일 안에서 다시 다른 파일을 #include할 수 있습니다 (중첩 include). 헤더 파일에는 함수 프로토타입, 구조체 정의, 매크로 상수, 여러 파일에서 공통으로 쓰는 선언들을 넣습니다.

대표적인 표준 헤더 파일

헤더 파일주요 내용대표 함수
<stdio.h> 기본 입출력, 파일 처리 printf, scanf, fopen, fclose, fread, fwrite, fseek…
<ctype.h> 문자 처리 isalpha, isupper, islower, toupper, tolower…
<string.h> 문자열·메모리 버퍼 처리 strlen, strcpy, strcat, strcmp, strtok, memcpy, memset…
<stdlib.h> 문자열 변환, 난수, 동적 할당, 실행 환경 atoi, atof, rand, srand, malloc, free, exit, abs…
<math.h> 수학 함수 (링크 시 -lm 필요) sin, cos, tan, exp, log, pow, sqrt, ceil, floor…
⚠️
math.h 사용 시 링크 옵션 필요! <math.h>의 함수를 사용할 때는 컴파일 시 -lm 옵션으로 수학 라이브러리를 링크해야 합니다:
$ gcc -o myprogram myprogram.c -lm
04

#define 단순 매크로 (Symbolic Constants)

🏷️단순 매크로 — 심볼릭 상수 정의

소스 파일 내의 모든 매크로 이름을 실제 매크로 정의 내용으로 텍스트 치환합니다.

#define macro_name  macro_value
#undef  macro_name   // 매크로 정의 무효화
심볼릭 상수 예시
C
#define SECONDS_PER_DAY (60 * 60 * 24) // 86400
#define PI              3.14159
#define C               299792.458    // 빛의 속도 (km/s)
#define MAX_SIZE        100
#define EOF             (-1)          // end-of-file 값
#define MAXINT          2147483647   // 4바이트 int 최댓값

/* C 연산자를 매크로로 별칭 정의 */
#define EQ   ==
#define NE   !=
#define AND  &&
#define OR   ||
#define NOT  !

📖문서화 (Documentation)

불명확한 상수 값을 의미 있는 이름으로 표현해 코드 가독성 향상

🔧이식성 (Portability)

시스템마다 달라지는 값을 #define 한 곳만 수정하면 전체 반영

🛡️신뢰성 (Reliability)

상수 실제값 확인을 #define 정의 부분만 보면 됨

매크로 텍스트 치환 시뮬레이터
05

#define 매개변수를 가진 매크로

⚡함수형 매크로 (Inline Function)

인자를 받아 함수처럼 동작하는 매크로입니다. 함수 호출 오버헤드 없이 실행 속도가 빠릅니다.

#define macro_name(arg1, …, argn) statements
// ⚠️ 매크로 이름과 ( 사이에 공백 없어야 함!
매개변수 매크로 예시
C
#define SQUARE(x)           ((x) * (x))
#define CUBE(x)             (SQUARE(x) * (x))
#define min(x, y)            (((x) < (y)) ? (x) : (y))
#define min4(a, b, c, d)     min(min(a,b), min(c,d))

/* 긴 정의는 '\' 로 다음 줄에 이어 쓰기 */
#define PRINT(x) if (debug == 1 && \
                      mode  == 1) \
                    printf("%d", x);
매개변수 매크로 확장 시뮬레이터

⚡매크로 장점 (vs 함수)

  • 함수 호출 오버헤드 없음 (빠른 실행)
  • 인자 복사, 복귀주소 저장, 리턴값 복사 등 메모리 연산 제거
  • 자주 사용되는 짧은 코드에 적합

⚠️매크로 단점 (vs 함수)

  • 복잡한 동작 정의 까다로움
  • 디버깅 어려움
  • 과도한 사용 시 실행 파일 크기 증가
  • 가독성 저하
06

매크로 정의의 잘못된 사용 예

❌인자에 괄호 없음

#define SQUARE(x) x * x

SQUARE(a + b);
// 확장: a + b * a + b
//         ≠ (a+b)*(a+b) !

✅인자 각각에 괄호

#define SQUARE(x) ((x) * (x))

SQUARE(a + b);
// 확장: ((a + b) * (a + b)) ✅

❌전체 수식 괄호 없음

#define SQUARE(x) (x) * (x)

4 / SQUARE(2);
// 확장: 4 / (2) * (2) = 4
//         ≠ 4 / ((2)*(2)) = 1 !

✅전체도 괄호로 감싸기

#define SQUARE(x) ((x) * (x))

4 / SQUARE(2);
// 확장: 4 / ((2) * (2)) = 1 ✅

❌매크로 이름과 ( 사이 공백 — 단순 매크로로 인식!

#define SQUARE (x) ((x) * (x))
//              ↑ 공백! → SQUARE가 문자열 "(x) ((x) * (x))"로 치환됨

SQUARE(7)
// 확장: (x) ((x) * (x))(7)  ← 완전히 잘못됨!

공백이 있으면 전처리기가 함수형 매크로가 아닌 단순 상수 매크로로 인식합니다.

❌매크로 정의 끝에 세미콜론 — 이중 세미콜론!

#define SQUARE(x) ((x) * (x)); // ← ; 주의!

x = SQUARE(y);
// 확장: x = ((y) * (y));; ← 세미콜론 2개 (일반 상황에서는 OK)

if (x == 2)
  x = SQUARE(y); // 확장: x = ((y)*(y));;
else              // ← 컴파일 syntax error!
  ++x;

if-else 구조에서 이중 세미콜론이 if 블록을 종료시켜 else가 if와 연결되지 않습니다.

✅
매크로 정의 황금 규칙 ① 각 인자를 괄호로 감싸기: ((x))
② 전체 수식도 괄호로 감싸기: ((x) * (x))
③ 이름과 ( 사이 공백 없애기: SQUARE(x)
④ 정의 끝에 세미콜론 쓰지 않기
07

사전 정의 매크로 (Predefined Macros)

🔮ANSI C 표준 사전 정의 매크로 5가지

프로그램 어디서나 사용 가능하며, 프로그래머가 재정의할 수 없습니다. 이름은 두 개의 밑줄로 시작하고 끝납니다. 주로 버전 관리와 디버깅에 사용합니다.

매크로값 (Value)활용 예
__TIME__ 컴파일 시각 문자열 (예: "14:23:01") 빌드 시각 로깅
__DATE__ 컴파일 날짜 문자열 (예: "Mar 16 2026") 빌드 날짜 표시
__LINE__ 현재 소스 코드 줄 번호 (정수) 에러 위치 추적
__FILE__ 현재 소스 파일명 문자열 에러 메시지에 파일명 포함
__STDC__ ANSI C 준수 여부 플래그 (1 = 준수) 이식성 코드 분기
사전 정의 매크로 활용 예시
C
#include <stdio.h>

int main(void) {
  printf("Build time : %s %s\n", __DATE__, __TIME__);
  printf("File       : %s\n", __FILE__);
  printf("Line       : %d\n", __LINE__);
  return 0;
}
// 실행 예시:
// Build time : Mar 16 2026 14:23:01
// File       : main.c
// Line       : 7

🐛디버그 매크로 패턴

/* 에러 위치 자동 포함 디버그 매크로 */
#define DEBUG_PRINT(msg) \
  fprintf(stderr, "[%s:%d] %s\n", __FILE__, __LINE__, msg)

/* 사용 예 */
FILE *fp = fopen("data.txt", "r");
if (fp == NULL)
  DEBUG_PRINT("파일 열기 실패");
// 출력: [main.c:15] 파일 열기 실패
08

조건부 컴파일 (Conditional Compilation)

🔀조건부 컴파일이란?

조건에 따라 소스 코드의 특정 부분만 선택적으로 컴파일합니다. 다중 플랫폼 이식성, 디버그/릴리즈 빌드 분리 등에 활용됩니다.

#if expr

수식의 결과가 0이 아니면 (True) 컴파일

#ifdef id

식별자가 #define으로 정의되어 있으면 컴파일

#ifndef id

식별자가 정의되어 있지 않으면 컴파일

조건부 컴파일 시뮬레이터

#if defined() — 논리 연산자 조합

플랫폼별 조건부 컴파일
C
#define RELEASE

/* DEBUG 정의O + RELEASE 정의X → Debug */
#if defined(DEBUG) && !defined(RELEASE)
  printf("Debug version!!!\n");
#elif !defined(DEBUG) && defined(RELEASE)
  printf("Release version!!!\n");  // ← 이 줄만 컴파일!
#else
  printf("Confusing version!!!\n");
#endif

/* OS별 코드 분기 */
#define LINUX
#if defined(LINUX) || defined(WINDOWS)
  printf("PC version!!!\n");        // ← 이 줄만 컴파일!
#elif defined(ANDROID) || defined(iOS)
  printf("Mobile version!!!\n");
#else
  printf("Hmm...\n");
#endif
09

컴파일러 옵션으로 매크로 정의 — gcc -D

⌨️소스 코드 외부에서 매크로 정의

소스 코드를 수정하지 않고 컴파일 시 명령어 옵션으로 매크로를 정의할 수 있습니다.

gcc -D 옵션 사용법Shell
# 매크로 이름만 정의 (값 없음)
$ gcc -DDEBUG -o output src.c
// → #define DEBUG 와 동일 효과

# 매크로 값 지정
$ gcc -DDEBUG=1 -o output src.c
// → #define DEBUG 1

$ gcc -DDEBUG=0 -o output src.c
// → #define DEBUG 0

📋소스 코드 (src.c)

// DEBUG는 소스에 정의 없음
#ifdef DEBUG
  printf("Debugging\n");
#endif
printf("Hello!\n");

🔨컴파일 방법별 결과

# DEBUG 없이 컴파일
$ gcc -o out src.c
→ 출력: Hello!  (Debugging 줄 제외)

# -DDEBUG 옵션으로 컴파일
$ gcc -DDEBUG -o out src.c
→ 출력: Debugging
          Hello!
💡
실무에서의 활용 빌드 시스템(Makefile, CMake 등)에서 debug/release 빌드를 구분할 때 -DDEBUG, -DRELEASE, -DPLATFORM_LINUX 등의 옵션을 자동으로 설정해 줍니다. 소스 코드를 수정하지 않고도 다양한 빌드 구성을 만들 수 있습니다.

QUIZ 01 / 06
#include <filename>과 #include "filename"의 차이는?
A 차이 없다. 둘 다 동일하게 동작한다.
B <>는 시스템 지정 위치에서, ""는 현재 디렉토리(또는 지정 경로)에서 먼저 탐색한다.
C <>는 C 파일을, ""는 헤더 파일만 포함할 수 있다.
D <>는 컴파일 시, ""는 런타임에 처리된다.
✅ 정답: B
<filename>: 시스템 헤더 파일 위치(Linux: /usr/include)에서 탐색 → 표준 라이브러리 헤더에 사용.
"filename": 현재 소스 파일 위치(또는 사용자 지정 경로)에서 먼저 탐색 → 사용자 정의 헤더에 사용.
QUIZ 02 / 06
#define SQUARE(x) ((x) * (x)) 일 때, SQUARE(7 + w)의 확장 결과는?
A 7 + w * 7 + w
B (7 + w) * (7 + w)
C ((7 + w) * (7 + w))
D ((7) + (w) * (7) + (w))
✅ 정답: C — ((7 + w) * (7 + w))
#define SQUARE(x) ((x) * (x))에서 x에 7 + w를 대입:
((7 + w) * (7 + w)) — 인자 전체와 수식 전체에 괄호가 올바르게 적용됩니다.
QUIZ 03 / 06
#define SQUARE(x) x * x일 때, SQUARE(a + b)의 확장 결과는?
A (a + b) * (a + b)
B a + b * a + b
C a * a + b * b
D (a + b * a + b)
✅ 정답: B — a + b * a + b
괄호 없이 x를 그대로 치환: a + b * a + b
연산자 우선순위에 의해 *가 먼저 계산되어 a + (b*a) + b가 됩니다.
의도한 결과 (a+b)*(a+b)와 완전히 다릅니다! → 인자에 괄호를 써야 합니다.
QUIZ 04 / 06
다음 코드에서 실제로 컴파일되는 printf는?
#define DEBUG
#undef  DEBUG
#ifdef  DEBUG
  printf("A\n");
#endif
#ifndef DEBUG
  printf("B\n");
#endif
A printf("A") 만 컴파일
B printf("B") 만 컴파일
C 둘 다 컴파일
D 둘 다 컴파일되지 않음
✅ 정답: B — printf("B") 만 컴파일
1. #define DEBUG로 DEBUG 정의
2. #undef DEBUG로 DEBUG 정의 무효화
3. #ifdef DEBUG: DEBUG가 정의되지 않았으므로 → A 블록 컴파일 안 됨
4. #ifndef DEBUG: DEBUG가 정의되지 않았으므로 → B 블록 컴파일됨
QUIZ 05 / 06
#define DEBUG 0일 때 다음 블록 중 컴파일되는 것은?
#if   DEBUG         printf("A\n"); #endif
#ifdef DEBUG         printf("B\n"); #endif
#ifndef DEBUG        printf("C\n"); #endif
A A와 B
B B만
C C만
D 모두 컴파일 안 됨
✅ 정답: B — B만 컴파일
#define DEBUG 0이므로 DEBUG는 정의되어 있음 (값은 0).
#if DEBUG: DEBUG == 0이므로 False → A 컴파일 안 됨
#ifdef DEBUG: DEBUG가 정의되어 있으므로 True → B 컴파일됨
#ifndef DEBUG: DEBUG가 정의되어 있으므로 False → C 컴파일 안 됨
⚠️ #if는 값(0인지 아닌지)을 보고, #ifdef는 정의 여부만 봅니다!
QUIZ 06 / 06
현재 소스 파일명과 줄 번호를 함께 출력하려면 어떤 사전 정의 매크로를 사용해야 하는가?
A __DATE__와 __TIME__
B __FILE__와 __LINE__
C __STDC__와 __LINE__
D __FILE__와 __DATE__

__FILE__: 현재 소스 파일명 문자열 (예: "main.c")
__LINE__: 현재 소스 코드 줄 번호 (정수)
